# Aula 14 — Spring AI

Objetivo: construir um assistente de trilhas com `ChatClient`, tool calling, RAG, memória de conversa e uma ferramenta externa via MCP.

Domínio: um guia de trilhas que responde dúvidas sobre dificuldade, duração e segurança. O catálogo local fornece dados estruturados; os guias indexados fornecem contexto textual; um servidor MCP fornece a previsão do tempo. O projeto é próprio desta aula.

## Base do projeto

```kotlin
implementation("org.springframework.boot:spring-boot-starter")
implementation("org.springframework.boot:spring-boot-starter-webmvc")
implementation("org.springframework.ai:spring-ai-starter-model-ollama")
implementation("org.springframework.ai:spring-ai-starter-mcp-client")
runtimeOnly("com.h2database:h2")
```

```kotlin
dependencyManagement {
    imports {
        mavenBom("org.springframework.ai:spring-ai-bom:2.0.0")
    }
}
```

O `webmvc` expõe a API do assistente. O starter do Ollama fornece chat e embeddings locais. O starter MCP conecta ferramentas externas. O H2 guarda o catálogo simples da aula; o `SimpleVectorStore` mantém os embeddings em memória.

A aplicação principal:

```java

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class TrailAssistantApplication {

    public static void main(String[] args) {
        SpringApplication.run(TrailAssistantApplication.class, args);
    }
}
```

## Conceitos

Spring AI conecta o Spring aos modelos de linguagem (LLM). A aplicação injeta um `ChatClient` em vez de montar HTTP, serialização e histórico na mão. Nesta aula, cada capacidade responde a uma pergunta diferente:

- **Chat**: `ChatClient` com prompt, system prompt e resposta estruturada.
- **Tool calling**: o modelo decide chamar um método seu e o Spring executa.
- **RAG**: embeddings + vector store devolvem contexto para o modelo responder sobre os guias da plataforma.

O provedor fica atrás das abstrações do Spring AI. Ollama roda localmente e evita chave de API nesta aula; OpenAI, Bedrock e Gemini exigem trocar o starter e a configuração. O código do assistente continua usando `ChatClient`.

## ChatClient

```java
package com.example.trailassistant.chat;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.stereotype.Service;

@Service
public class TrailAssistantService {

    private final ChatClient chatClient;

    public TrailAssistantService(ChatClient.Builder builder) {
        this.chatClient = builder
                .defaultSystem("Você é um guia de trilhas. Responda em português, não invente dados e avise quando não souber.")
                .build();
    }

    public String ask(String conversationId, String question) {
        return chatClient.prompt()
                .advisors(advisors -> advisors.param(ChatMemory.CONVERSATION_ID, conversationId))
                .user(question)
                .call()
                .content();
    }
}
```

O `system` define o comportamento estável do assistente; o `user` carrega a pergunta daquela interação; `call().content()` devolve o texto. O modelo ainda pode errar: um system prompt não transforma conhecimento externo em fato. RAG e tools entram justamente para fornecer dados verificáveis.

Exponha o chat pela API:

```java
package com.example.trailassistant.web;

import com.example.trailassistant.chat.TrailAssistantService;

    public AssistantController(TrailAssistantService assistantService) {
        this.assistantService = assistantService;

    }

    }
```

## Tool calling

Ferramenta é um método seu que o modelo pode invocar. Ela deve ter uma descrição clara, argumentos simples e retorno que o modelo consiga interpretar:

```java
package com.example.trailassistant.chat;

import java.util.List;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.stereotype.Component;

@Component
public class TrailTools {

    @Tool(description = "Busca trilhas por região e dificuldade")
    public List<Trail> findTrails(String region, String difficulty) {
        return List.of(
                new Trail("Morro da Urca", "Rio de Janeiro", "easy", 2.0),
                new Trail("Pedra da Gávea", "Rio de Janeiro", "hard", 6.0));
    }

    public record Trail(String name, String region, String difficulty, double distanceKm) {
    }
}
```

Registre a ferramenta no cliente. O modelo recebe a descrição e escolhe a chamada; o usuário não chama o método diretamente:

```java
public TrailAssistantService(ChatClient.Builder builder, TrailTools tools) {
    this.chatClient = builder
            .defaultSystem("Você é um guia de trilhas. Use a ferramenta quando precisar consultar o catálogo.")
            .defaultTools(tools)
            .build();
}
```

Quando a pergunta exige um dado do catálogo, o modelo devolve uma chamada de tool; o Spring executa o método, devolve o resultado e o modelo completa a resposta. A ferramenta não deve aceitar operações perigosas sem validação: o modelo escolhe quando chamar, mas o código continua responsável por autorizar e validar o efeito.

## RAG

O modelo responde bem sobre o que sabe, e inventa sobre o que não sabe. RAG injeta contexto seu no prompt: você indexa documentos, e na pergunta busca os mais parecidos.

Embeddings são vetores que representam o texto; a busca por similaridade acha trechos relevantes mesmo sem palavra exata. O `VectorStore` guarda esses vetores. `SimpleVectorStore` roda em memória, bom pra demonstrar; produção usa PGVector, Redis ou Qdrant.

```java
package com.example.trailassistant.config;

import org.springframework.ai.embedding.EmbeddingModel;
import org.springframework.ai.vectorstore.SimpleVectorStore;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class VectorStoreConfiguration {

    @Bean
    VectorStore vectorStore(EmbeddingModel embeddingModel) {
        return SimpleVectorStore.builder(embeddingModel).build();
    }
}
```

Os guias são os documentos que o modelo não conhece. Indexe o texto uma vez antes de perguntar:

```java
package com.example.trailassistant.rag;

import java.util.List;
import java.util.Map;

import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.stereotype.Component;

@Component
public class TrailGuideIndexer {

    private final VectorStore vectorStore;

    public TrailGuideIndexer(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    public void index() {
        vectorStore.add(List.of(
                new Document(
                        "A trilha do Morro da Urca tem dificuldade fácil, dois quilômetros e sombra parcial. Evite depois de chuva forte.",
                        Map.of("trail", "morro-da-urca")),
                new Document(
                        "A Pedra da Gávea tem dificuldade difícil, seis quilômetros e trechos expostos. Exige preparo e previsão estável.",
                        Map.of("trail", "pedra-da-gavea"))));
    }
}
```

Exponha a indexação para que a etapa fique explícita e repetível:

```java
package com.example.trailassistant.web;

import com.example.trailassistant.rag.TrailGuideIndexer;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/assistant")
public class IndexController {

    private final TrailGuideIndexer indexer;

    public IndexController(TrailGuideIndexer indexer) {
        this.indexer = indexer;
    }

    @PostMapping("/index")
    public ResponseEntity<Void> index() {
        indexer.index();
        return ResponseEntity.noContent().build();
    }
}
```

O `QuestionAnswerAdvisor` automatiza a busca: pega a pergunta, consulta o vector store e junta o contexto no prompt antes de chamar o modelo:

```java
public TrailAssistantService(ChatClient.Builder builder, TrailTools tools, VectorStore vectorStore) {
    this.chatClient = builder
            .defaultSystem("Responda usando os guias fornecidos. Se a informação não estiver no contexto, diga que não sabe.")
            .defaultTools(tools)
            .defaultAdvisors(QuestionAnswerAdvisor.builder(vectorStore).build())
            .build();
}
```

`QuestionAnswerAdvisor` é de `org.springframework.ai.chat.client.advisor`. Primeiro rode `POST /api/assistant/index`; depois pergunte sobre chuva ou dificuldade. Pergunte algo fora dos guias e observe o modelo admitir que o contexto não responde. RAG reduz alucinação, mas não garante verdade: a qualidade depende dos documentos recuperados.

## Memória

Advisor de memória guarda o histórico da conversa, então o modelo lembra do que foi dito antes:

```java
package com.example.trailassistant.config;

import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.chat.memory.MessageWindowChatMemory;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MemoryConfiguration {

    @Bean
    ChatMemory chatMemory() {
        return MessageWindowChatMemory.builder()
                .maxMessages(20)
                .build();
    }
}
```

Adicione o advisor ao mesmo `ChatClient` que já usa tool e RAG:

```java
public TrailAssistantService(ChatClient.Builder builder,
                             TrailTools tools,
                             VectorStore vectorStore,
                             ChatMemory chatMemory) {
    this.chatClient = builder
            .defaultTools(tools)
            .defaultAdvisors(QuestionAnswerAdvisor.builder(vectorStore).build())
            .defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())
            .build();
}
```

`MessageChatMemoryAdvisor` insere mensagens anteriores no prompt. O `conversationId` passado em `advisors.param(...)` separa as conversas; sem ele, sessões diferentes podem compartilhar histórico. `ChatMemory` em memória serve para a demonstração e some no restart. Em produção, persista por conversa. Cada advisor empilha um comportamento: RAG traz contexto, memória traz histórico e tool dá acesso ao catálogo.

## MCP

O cliente já tem `spring-ai-starter-mcp-client` na base. O servidor de previsão é um projeto separado:

```kotlin
implementation("org.springframework.ai:spring-ai-starter-mcp-server-webmvc")
```

O servidor expõe a ferramenta por Streamable HTTP:

```java
package com.example.weathermcp;

import org.springframework.ai.mcp.server.annotation.McpTool;
import org.springframework.stereotype.Component;

@Component
public class WeatherTools {

    @McpTool(description = "Consulta a previsão atual para uma região")
    public Forecast forecast(String region) {
        return new Forecast(region, "sem chuva", 24);
    }

    public record Forecast(String region, String condition, int temperatureCelsius) {
    }
}
```

Configure esse servidor na porta `8081`:

```yaml
server:
  port: 8081
spring:
  ai:
    mcp:
      server:
        protocol: STREAMABLE
```

O Model Context Protocol padroniza a conexão do modelo a ferramentas externas. O cliente do assistente consome as ferramentas; o servidor MCP expõe as suas sem o assistente conhecer a implementação.

Cliente, via config:

```yaml
spring:
  ai:
    mcp:
      client:
        streamable-http:
          connections:
            weather-server:
              url: http://localhost:8081
```

As ferramentas do servidor MCP entram no `ChatClient` como `ToolCallbackProvider`, do mesmo jeito que as locais via `@Tool`:

```java
import org.springframework.ai.tool.ToolCallbackProvider;

public TrailAssistantService(ChatClient.Builder builder,
                             TrailTools localTools,
                             ToolCallbackProvider weatherTools) {
    this.chatClient = builder
            .defaultTools(localTools)
            .defaultToolCallbacks(weatherTools)
            .build();
}
```

Suba o servidor MCP antes do assistente e pergunte `Qual é a previsão para a Tijuca?`. O modelo pode chamar a ferramenta remota e incluir o resultado na resposta. Em produção, autentique o transporte e trate timeout e indisponibilidade como qualquer outra dependência de rede.
