# Aula 14 — Spring AI

Objetivo: construir um assistente de trilhas com `ChatClient`, tool calling, RAG, memória de conversa e uma ferramenta externa via MCP.

Domínio: um guia de trilhas que responde dúvidas sobre dificuldade, duração e segurança. O catálogo local fornece dados estruturados; os guias indexados fornecem contexto textual; um servidor MCP fornece a previsão do tempo. O projeto é próprio desta aula.

## Dados

O assistente usa duas bases: um catálogo de trilhas, que é dado estruturado pro tool, e o texto dos guias, que alimenta o RAG. Os dois vêm de fontes públicas, extraídas uma vez e commitadas em `src/main/resources/data/`.

- Catálogo: OpenStreetMap, via Overpass API. As trilhas aparecem como `way` com `highway=path` ou `highway=footway`, e a tag `sac_scale` traz a dificuldade técnica. Licença ODbL, com atribuição.
- Guias: Wikipédia, via API do MediaWiki com `prop=extracts&explaintext=1`, que devolve o texto limpo do artigo. Licença CC BY-SA, com atribuição.

A extração roda uma vez, fora da aplicação. Ela fica em `trail-assistant/src/main/resources/extract-data.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

script_dir=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)
data_dir="$script_dir/data"
mkdir -p "$data_dir/guides"

curl -sG -A "trail-assistant/1.0" https://overpass-api.de/api/interpreter \
  --data-urlencode 'data=[out:json][timeout:60][bbox:-23.05,-43.45,-22.85,-43.15];
    way["highway"~"path|footway"]["name"]["sac_scale"];
    out tags;' \
| jq -r '
  def difficulty:
    if . == null then "moderate"
    elif (. == "strolling" or . == "hiking") then "easy"
    elif . == "mountain_hiking" then "moderate"
    else "hard" end;
  ["name","region","difficulty","distanceKm"],
  (.elements[]
   | select(.tags.name != null)
   | [ .tags.name,
       "Rio de Janeiro",
       ( .tags.sac_scale | difficulty ),
       ( .tags.distance // "" | sub(" km$"; "") ) ])
  | @csv' > "$data_dir/trails.csv"

for title in "Pedra da Gávea" "Pico da Tijuca" "Pedra Bonita" "Morro da Urca"; do
  slug=$(printf '%s' "$title" | iconv -f utf-8 -t ascii//TRANSLIT | tr '[:upper:] ' '[:lower:]-')
  curl -sG "https://pt.wikipedia.org/w/api.php" \
    --data-urlencode "action=query" \
    --data-urlencode "prop=extracts" \
    --data-urlencode "explaintext=1" \
    --data-urlencode "format=json" \
    --data-urlencode "titles=$title" \
  | jq -r '.query.pages[] | select(.extract != null) | .extract' > "$data_dir/guides/$slug.md"
done
```

Para rodar, a partir de `trail-assistant/`:

```bash
chmod +x src/main/resources/extract-data.sh
./src/main/resources/extract-data.sh
```

O script resolve os caminhos a partir da própria pasta, então grava sempre em `trail-assistant/src/main/resources/data/`, sem duplicar. O `-A` manda o `User-Agent`; sem ele, o Overpass responde `406 Not Acceptable` com uma página HTML e o `jq` quebra. O Overpass é um serviço comunitário, então rode uma vez e commite os arquivos; a aplicação lê o CSV e os `.md` do classpath, sem tocar na rede.

O `trails.csv` sai com cabeçalho e linhas neste formato:

```csv
"name","region","difficulty","distanceKm"
"Trilha da Pedra da Gávea","Rio de Janeiro","hard",""
```

O `distance` vem vazio na maioria das trilhas do OSM, e o campo `distanceKm` da entidade aceita nulo.

Cada arquivo de `src/main/resources/data/guides/` guarda o texto de um guia, e o nome do arquivo serve de identificador. O tool lê o CSV e grava no Postgres; o RAG lê os `.md` e indexa.

A lista de títulos do loop é curada: nem toda trilha do OSM tem artigo na Wikipédia, então só entram as que têm. Por isso o catálogo tem dezenas de linhas e os guias são poucos, o que também deixa explícito o limite do RAG na seção de testes.

## Conceitos

Spring AI conecta o Spring aos modelos de linguagem (LLM). A aplicação injeta um `ChatClient` em vez de montar HTTP, serialização e histórico na mão. Nesta aula, cada capacidade responde a uma pergunta diferente:

- **Chat**: `ChatClient` com prompt, system prompt e resposta estruturada.
- **Tool calling**: o modelo decide chamar um método seu e o Spring executa.
- **RAG**: os embeddings no pgvector recuperam trechos dos guias e o modelo responde com esse contexto.

O provedor fica atrás das abstrações do Spring AI. Ollama roda localmente e evita chave de API nesta aula; OpenAI, Bedrock e Gemini exigem trocar o starter e a configuração. O código do assistente continua usando `ChatClient`.

## ChatClient

```java
package com.example.trailassistant.chat;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;

@Service
public class TrailAssistantService {

    private final ChatClient chatClient;

    public TrailAssistantService(ChatClient.Builder builder) {
        this.chatClient = builder
                .defaultSystem("Você é um guia de trilhas. Responda em português, não invente dados e avise quando não souber.")
                .build();
    }

    public String ask(String question) {
        return chatClient.prompt()
                .user(question)
                .call()
                .content();
    }
}
```

O `system` define o comportamento estável do assistente; o `user` carrega a pergunta daquela interação; `call().content()` devolve o texto. O modelo ainda pode errar: um system prompt não transforma conhecimento externo em fato. RAG e tools entram justamente para fornecer dados verificáveis.

## Tool calling

Ferramenta é um método seu que o modelo pode invocar. Ela deve ter uma descrição clara, argumentos simples e retorno que o modelo consiga interpretar. Aqui a ferramenta consulta o catálogo de trilhas no Postgres.

O catálogo vira uma entidade JPA:


Na subida, um `ApplicationRunner` lê o CSV e popula a tabela. O `count()` evita duplicar a cada boot:

```java
package com.example.trailassistant.trail;

import java.io.IOException;
import java.io.UncheckedIOException;
import java.nio.charset.StandardCharsets;
import java.util.List;

import org.springframework.boot.ApplicationArguments;
import org.springframework.boot.ApplicationRunner;
import org.springframework.core.io.ClassPathResource;
import org.springframework.stereotype.Component;

@Component
public class TrailCatalogLoader implements ApplicationRunner {

    private final TrailRepository trailRepository;

    public TrailCatalogLoader(TrailRepository trailRepository) {
        this.trailRepository = trailRepository;
    }

    @Override
    public void run(ApplicationArguments args) {
        if (trailRepository.count() > 0) {
            return;
        }
        trailRepository.saveAll(readCatalog());
    }

    private List<Trail> readCatalog() {
        var resource = new ClassPathResource("data/trails.csv");
        try (var lines = resource.getContentAsString(StandardCharsets.UTF_8).lines()) {
            return lines.skip(1)
                    .filter(line -> !line.isBlank())
                    .map(this::toTrail)
                    .toList();
        } catch (IOException exception) {
            throw new UncheckedIOException(exception);
        }
    }

    private Trail toTrail(String line) {
        var columns = line.split(",");
        var distanceKm = unquote(columns[3]);
        return new Trail(
                unquote(columns[0]),
                unquote(columns[1]),
                unquote(columns[2]),
                distanceKm.isBlank() ? null : Double.valueOf(distanceKm));
    }

    private String unquote(String value) {
        return value.replace("\"", "");
    }
}
```

## RAG

O modelo responde bem sobre o que sabe, e inventa sobre o que não sabe. RAG injeta contexto seu no prompt: você indexa documentos, e na pergunta busca os mais parecidos.

Embeddings são vetores que representam o texto, e a busca por similaridade acha trechos relevantes mesmo sem palavra exata. O starter do pgvector configura o `VectorStore` apontando pro Postgres, então não existe bean pra criar: a tabela `vector_store` guarda os vetores e o índice HNSW faz a busca.

Os guias ficam em `src/main/resources/data/guides/`. A indexação lê cada arquivo, quebra em pedaços e grava os vetores:

```java
package com.example.trailassistant.rag;

import java.io.IOException;
import java.io.UncheckedIOException;
import java.util.List;

import org.springframework.ai.document.Document;
import org.springframework.ai.reader.TextReader;
import org.springframework.ai.transformer.splitter.TokenTextSplitter;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.core.io.Resource;
import org.springframework.core.io.support.PathMatchingResourcePatternResolver;
import org.springframework.stereotype.Component;

@Component
public class TrailGuideIndexer {

    private final VectorStore vectorStore;

    public TrailGuideIndexer(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    public void index() {
        var splitter = TokenTextSplitter.builder()
                .withChunkSize(800)
                .withMinChunkSizeChars(350)
                .withKeepSeparator(true)
                .build();

        for (var guide : guides()) {
            var reader = new TextReader(guide);
            reader.getCustomMetadata().put("source", guide.getFilename());
            List<Document> chunks = splitter.apply(reader.get());
            vectorStore.add(chunks);
        }
    }

    private Resource[] guides() {
        try {
            return new PathMatchingResourcePatternResolver()
                    .getResources("classpath:data/guides/*.md");
        } catch (IOException exception) {
            throw new UncheckedIOException(exception);
        }
    }
}
```

O `TokenTextSplitter` quebra o texto em blocos de 800 tokens, com um mínimo de 350 caracteres por bloco. O `TextReader` grava o nome do arquivo na metadata `source`, que depois serve de filtro.

Exponha a indexação para que a etapa fique explícita. Execute esse request uma vez depois de iniciar a aplicação:

A busca vai além de pegar os N mais parecidos. O `RetrievalAugmentationAdvisor` monta o fluxo modular: recupera os documentos e injeta o contexto no prompt. Aqui ele usa o `VectorStoreDocumentRetriever` com `topK` e `similarityThreshold`:

```java
package com.example.trailassistant.chat;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;
import org.springframework.ai.rag.retrieval.search.VectorStoreDocumentRetriever;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.stereotype.Service;

@Service
public class TrailAssistantService {

    private final ChatClient chatClient;

    public TrailAssistantService(ChatClient.Builder builder,
                                 TrailTools tools,
                                 VectorStore vectorStore) {
        var retrieval = RetrievalAugmentationAdvisor.builder()
                .documentRetriever(VectorStoreDocumentRetriever.builder()
                        .vectorStore(vectorStore)
                        .topK(5)
                        .similarityThreshold(0.2)
                        .build())
                .build();

        this.chatClient = builder
                .defaultSystem("Responda usando os guias fornecidos. Se a informação não estiver no contexto, diga que não sabe.")
                .defaultTools(tools)
                .defaultAdvisors(retrieval)
                .build();
    }

    public String ask(String question) {
        return chatClient.prompt()
                .user(question)
                .call()
                .content();
    }
}
```

O `similarityThreshold` corta resultado ruim. Sem ele, a busca sempre devolve os cinco vizinhos mais próximos, mesmo quando nenhum tem a ver, e o modelo responde em cima de ruído. O retriever também aceita `filterExpression` pra restringir por metadata, por exemplo filtrar pelo `source` de um guia; o filtro pode vir por request com o parâmetro `VectorStoreDocumentRetriever.FILTER_EXPRESSION`.

Primeiro indexe os guias:

```http
POST http://localhost:8080/api/assistant/index
```

O endpoint responde `204 No Content`. O pgvector persiste os vetores entre reinícios, então indexe uma vez. Rodar o `POST /api/assistant/index` de novo duplica os pedaços; pra reindexar do zero, limpe a tabela com `TRUNCATE vector_store`.

Com o índice pronto, pergunte um detalhe que só existe no texto do guia. A Pedra da Gávea tem guia indexado, e o catálogo não guarda esse tipo de informação. A resposta se apoia no trecho recuperado:

```http
### RAG: trilha com guia indexado
POST http://localhost:8080/api/assistant/ask
Content-Type: application/json

{
  "question": "Preciso de algum cuidado especial para subir a Pedra da Gávea?"
}
```

Agora pergunte sobre uma trilha que está no catálogo mas não tem guia. O `VectorStoreDocumentRetriever` não passa do `similarityThreshold`, o contexto chega vazio e o `RetrievalAugmentationAdvisor` instrui o modelo a não responder o que não tem:

```http
### RAG: trilha sem guia indexado
POST http://localhost:8080/api/assistant/ask
Content-Type: application/json

{
  "question": "A trilha do Caminho da Lagartixa tem trecho exposto?"
}
```

O contraste é o ponto da seção: o tool enxerga o catálogo inteiro, o RAG só enxerga os guias indexados. O modelo responde o que o contexto permite e admite quando não tem. RAG reduz alucinação, mas não garante verdade: a qualidade depende dos documentos recuperados.

### Outras alavancas

O caminho principal é indexar, buscar e injetar. Quando a qualidade não basta, as alavancas se dividem em três grupos:

- Antes de buscar: `RewriteQueryTransformer`, que reescreve a pergunta, `MultiQueryExpander`, que gera variações dela, e HyDE, que embeda uma resposta hipotética em vez da pergunta. Cada um adiciona uma chamada de LLM antes da busca.
- Na busca: densa mais esparsa (BM25) com fusão dos rankings, filtro por metadata e `similarityThreshold`.
- Depois de buscar: reordenação com um cross-encoder. O Spring AI 2.0 não traz reranker pronto, e o ponto de extensão é a interface `DocumentPostProcessor`, passada em `documentPostProcessors(...)`.

Avaliação fecha o ciclo. `RelevancyEvaluator` mede se a resposta faz sentido dado o contexto, e `FactCheckingEvaluator` mede se a afirmação se sustenta no contexto. Os dois usam o próprio modelo como juiz e leem o contexto recuperado da constante `RetrievalAugmentationAdvisor.DOCUMENT_CONTEXT`. Sem medir, você não sabe se a mudança melhorou ou só mudou.

## Memória

Substitua `TrailAssistantService` por esta versão. Ela mantém as tools e o RAG e acrescenta o advisor de memória:

```java
package com.example.trailassistant.chat;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;
import org.springframework.ai.rag.retrieval.search.VectorStoreDocumentRetriever;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.stereotype.Service;

@Service
public class TrailAssistantService {

    private final ChatClient chatClient;

    public TrailAssistantService(ChatClient.Builder builder,
                                 TrailTools tools,
                                 VectorStore vectorStore,
                                 ChatMemory chatMemory) {
        var retrieval = RetrievalAugmentationAdvisor.builder()
                .documentRetriever(VectorStoreDocumentRetriever.builder()
                        .vectorStore(vectorStore)
                        .topK(5)
                        .similarityThreshold(0.5)
                        .build())
                .build();

        this.chatClient = builder
                .defaultSystem("Responda usando os guias fornecidos. Se a informação não estiver no contexto, diga que não sabe.")
                .defaultTools(tools)
                .defaultAdvisors(
                        retrieval,
                        MessageChatMemoryAdvisor.builder(chatMemory).build())
                .build();
    }

    public String ask(String conversationId, String question) {
        return chatClient.prompt()
                .advisors(advisors -> advisors.param(ChatMemory.CONVERSATION_ID, conversationId))
```

O Model Context Protocol padroniza a conexão do modelo a ferramentas externas. O cliente do assistente consome as ferramentas; o servidor MCP expõe as suas sem o assistente conhecer a implementação.

Substitua o `application.yaml` do `trail-assistant` pelo arquivo completo abaixo:


O nome `weather-server` identifica a conexão MCP. O starter cria um `ToolCallbackProvider` com as ferramentas descobertas nessa conexão.

As ferramentas do servidor MCP entram no `ChatClient` como `ToolCallbackProvider`, do mesmo jeito que as locais via `@Tool`:

```java
package com.example.trailassistant.chat;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;
import org.springframework.ai.rag.retrieval.search.VectorStoreDocumentRetriever;
import org.springframework.ai.tool.ToolCallbackProvider;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.stereotype.Service;

@Service
public class TrailAssistantService {

    private final ChatClient chatClient;

    public TrailAssistantService(ChatClient.Builder builder,
                                 TrailTools localTools,
                                 VectorStore vectorStore,
                                 ChatMemory chatMemory,
                                 ToolCallbackProvider weatherTools) {
        var retrieval = RetrievalAugmentationAdvisor.builder()
                .documentRetriever(VectorStoreDocumentRetriever.builder()
                        .vectorStore(vectorStore)
                        .topK(5)
                        .similarityThreshold(0.5)
                        .build())
                .build();

        this.chatClient = builder
                .defaultSystem("Responda usando os guias e consulte a previsão quando a pergunta depender do clima.")
                .defaultTools(localTools)
                .defaultToolCallbacks(weatherTools)
                .defaultAdvisors(
                        retrieval,
                        MessageChatMemoryAdvisor.builder(chatMemory).build())
                .build();
    }

    public String ask(String conversationId, String question) {
        return chatClient.prompt()
                .advisors(advisors -> advisors.param(ChatMemory.CONVERSATION_ID, conversationId))
                .user(question)
                .call()
                .content();
    }
}
```
