# Aula 15 — Spring AI

Objetivo: plugar um modelo de linguagem com `ChatClient`, dar ferramentas via tool calling, e responder com contexto via RAG.

## Conceitos

Spring AI é a camada que conecta o Spring aos modelos de linguagem (LLM). Você não fala com a API do provedor na mão; injeta um `ChatClient` e conversa. Em cima disso, o framework resolve as três coisas que um agente precisa:

- **Chat**: `ChatClient` com prompt, system prompt e resposta estruturada.
- **Tool calling**: o modelo decide chamar um método seu e o Spring executa.
- **RAG**: embeddings + vector store devolvem contexto pro modelo responder sobre dados seus.

O provedor (OpenAI, Ollama, Bedrock, Gemini) fica atrás de uma interface. Trocar de modelo é trocar o starter e a config, não o código.

## Dependências

```kotlin
dependencyManagement {
    imports {
        mavenBom("org.springframework.ai:spring-ai-bom:2.0.0")
    }
}

dependencies {
    implementation("org.springframework.ai:spring-ai-starter-model-ollama")
    implementation("org.springframework.ai:spring-ai-starter-mcp-client")
}
```

Ollama roda um modelo local, sem chave de API, o que deixa a aula reproduzível. Pra OpenAI, troque o starter por `spring-ai-starter-model-openai` e a config por `spring.ai.openai.api-key`.

## ChatClient

```java
package com.example.assistant.chat;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;

@Service
public class AssistantService {

    private final ChatClient chatClient;

    public AssistantService(ChatClient.Builder builder) {
        this.chatClient = builder
                .defaultSystem("Você ajuda a catalogar livros de uma biblioteca. Responda em português.")
                .build();
    }

    public String ask(String question) {
        return chatClient.prompt()
                .user(question)
                .call()
                .content();
    }
}
```

O `system` define o papel; o `user` é a pergunta; `call().content()` devolve o texto da resposta. Config do Ollama:

```yaml
spring:
  ai:
    ollama:
      base-url: http://localhost:11434
      chat:
        options:
          model: llama3.1
```

## Tool calling

Ferramenta é um método seu que o modelo pode invocar. Anote com `@Tool`:

```java
package com.example.assistant.chat;

import java.util.List;

import com.example.assistant.book.Book;
import com.example.assistant.book.BookRepository;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.stereotype.Component;

@Component
public class BookTools {

    private final BookRepository repository;

    public BookTools(BookRepository repository) {
        this.repository = repository;
    }

    @Tool(description = "Busca os livros de um autor")
    public List<Book> findByAuthor(String author) {
        return repository.findByAuthor(author);
    }
}
```

Registre a ferramenta no cliente:

```java
public AssistantService(ChatClient.Builder builder, BookTools tools) {
    this.chatClient = builder
            .defaultSystem("Você ajuda a catalogar livros de uma biblioteca.")
            .defaultTools(tools)
            .build();
}
```

Quando a pergunta exige dado que o modelo não tem, ele devolve uma chamada de tool; o Spring executa o método, devolve o resultado e o modelo completa a resposta. O `@Tool(description)` é o que o modelo lê pra decidir quando chamar.

## RAG

O modelo responde bem sobre o que sabe, e inventa sobre o que não sabe. RAG injeta contexto seu no prompt: você indexa documentos, e na pergunta busca os mais parecidos.

Embeddings são vetores que representam o texto; a busca por similaridade acha trechos relevantes mesmo sem palavra exata. O `VectorStore` guarda esses vetores. `SimpleVectorStore` roda em memória, bom pra demonstrar; produção usa PGVector, Redis ou Qdrant.

```java
package com.example.assistant.config;

import org.springframework.ai.embedding.EmbeddingModel;
import org.springframework.ai.vectorstore.SimpleVectorStore;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class VectorStoreConfiguration {

    @Bean
    VectorStore vectorStore(EmbeddingModel embeddingModel) {
        return SimpleVectorStore.builder(embeddingModel).build();
    }
}
```

Indexar o catálogo:

```java
package com.example.assistant.chat;

import java.util.List;
import java.util.Map;

import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.stereotype.Component;

import com.example.assistant.book.Book;
import com.example.assistant.book.BookRepository;

@Component
public class CatalogIndexer {

    private final VectorStore vectorStore;
    private final BookRepository repository;

    public CatalogIndexer(VectorStore vectorStore, BookRepository repository) {
        this.vectorStore = vectorStore;
        this.repository = repository;
    }

    public void index() {
        for (Book book : repository.findAll()) {
            Document document = new Document(
                    "Título: " + book.title() + ". Autor: " + book.author(),
                    Map.of("bookId", book.id()));
            vectorStore.add(List.of(document));
        }
    }
}
```

O `QuestionAnswerAdvisor` automatiza a busca: pega a pergunta, consulta o vector store e junta o contexto no prompt antes de chamar o modelo:

```java
public AssistantService(ChatClient.Builder builder, BookTools tools, VectorStore vectorStore) {
    this.chatClient = builder
            .defaultSystem("Responda usando o contexto fornecido. Se não estiver lá, diga que não sabe.")
            .defaultTools(tools)
            .defaultAdvisors(QuestionAnswerAdvisor.builder(vectorStore).build())
            .build();
}
```

`QuestionAnswerAdvisor` é de `org.springframework.ai.chat.client.advisor`. Com ele, "quais livros de poesia temos?" busca os documentos de poesia e o modelo responde com o catálogo, sem alucinar títulos.

## Memória

Advisor de memória guarda o histórico da conversa, então o modelo lembra do que foi dito antes:

```java
public AssistantService(ChatClient.Builder builder, ChatMemory chatMemory) {
    this.chatClient = builder
            .defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())
            .build();
}
```

`MessageChatMemoryAdvisor` insere as mensagens anteriores no prompt. `ChatMemory` em memória serve pra sessão curta; produção persiste por conversa. Cada advisor empilha um comportamento: RAG traz contexto, memória traz histórico, tool dá acesso a dados.

## MCP

O Model Context Protocol padroniza a conexão do modelo a ferramentas externas. O Spring AI fala dos dois lados: um MCP client consome ferramentas de um servidor, e um MCP server expõe as suas.

Cliente, via config:

```yaml
spring:
  ai:
    mcp:
      client:
        streamable-http:
          connections:
            weather-server:
              url: http://localhost:8080
```

As ferramentas do servidor MCP entram no `ChatClient` como `ToolCallbackProvider`, do mesmo jeito que as locais via `@Tool`. Servidor, você anota métodos com `@McpTool` e o Spring expõe via Streamable HTTP ou stdio. MCP é o que faz o agente plugar ferramentas de terceiros sem escrever adaptador.
